Features & How It Works

Everything Sourcebound does, end to end

From ingesting a source to answering a question with references, every step is grounded in what the backend actually does — nothing here is aspirational.

Website ingestion

Add any public http/https URL. Requests enforce timeouts and response-size limits, and unsafe schemes such as file:// or javascript: are rejected.

Document upload

Upload .pdf, .txt, or .md files. Extension, MIME type, and size are all validated server-side before a file is trusted.

Cleaning, normalization & chunking

Extracted text is cleaned and normalized, then split into configurable, overlapping chunks sized for retrieval quality.

Local embeddings & storage

Each chunk is embedded with an OpenAI embedding model and stored as local NumPy vectors — no external vector database.

Cosine-similarity retrieval

At query time the question is embedded and compared against a source's chunks to find the top-k most relevant passages.

Source-grounded chat

The chat model answers only from the retrieved context, and returns a clear "not found in this source" reply when the context is insufficient.

Per-answer references

Every answer carries a Sources button that opens the exact chunk excerpts used to ground it.

Validated everywhere

Every endpoint validates input with Pydantic and returns structured errors — never a raw stack trace or filesystem path.

Full state coverage

Loading, empty, validation-error, network-error, and backend-error states are handled throughout the interface.

How it works

From a raw source to a searchable knowledge base

1

Validation

The URL or file is checked — scheme, size, extension, and MIME type — before anything is processed.

2

Content extraction

Readable text is pulled from the webpage or document (PDF, TXT, or Markdown).

3

Cleaning & normalization

Boilerplate, whitespace, and encoding noise are cleaned up before chunking.

4

Chunking

Text is split into overlapping chunks sized for retrieval, using configurable chunk size and overlap.

5

Embedding generation

Each chunk is embedded with the configured OpenAI embedding model.

6

Ready for retrieval

Embeddings are stored locally, and the source status flips to Ready in the workspace.

Then, in chat

Ask, retrieve, answer, cite

1. Ask a question

Pick a ready source and type a question in the composer.

2. Retrieval runs

A "Searching your sources…" state shows while the top-k relevant chunks are found.

3. Answer generated

The model answers strictly from the retrieved context, or says the content isn't found.

4. Sources button

A Sources button appears when references exist, opening the exact excerpts used.

Supported source formats

Format Extension Notes
Website http(s):// Public pages only; file://, javascript:, and ftp:// are rejected.
PDF .pdf Text-based PDFs; scanned/image-only PDFs may extract no text.
Plain text .txt UTF-8 encoded.
Markdown .md Headings preserved where possible.
