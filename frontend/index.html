What it does

Three steps from source to answer

Add a source

Paste a public website URL, or upload a local PDF, TXT, or Markdown file.

It gets indexed

The backend extracts, cleans, chunks, and embeds the content into local vector storage.

Ask questions

Select the source in chat and ask — answers come only from retrieved chunks, with references.

Grounded, not guessed

Retrieval-augmented generation, without the fabrication

When you ask a question, Sourcebound embeds it and compares it against the selected source's chunk embeddings using local NumPy cosine-similarity search — no external vector database. The most relevant chunks are assembled into a context package, and the chat model is constrained to answer only from that context.

If the answer isn't in the retrieved content, you get a clear "not found in this source" response instead of a fabricated one, and every answer that does succeed comes with a Sources button linking back to the exact chunks used.

Local vector storage

JSON + NumPy files under backend/data/ — no database, no Docker.

Strictly source-bound answers

The model is constrained to the retrieved context for every response.

Traceable references

Every answer links back to the source chunks that produced it.

Capabilities

Built for grounded knowledge work

Website ingestion

Protocol, size, and timeout safety checks with readable-text extraction from any public URL.

Document upload

PDF, TXT, and Markdown, validated by extension, MIME type, and size before processing.

Cleaning & chunking

Text is normalized and split into overlapping, configurable chunks for retrieval.

Local vector retrieval

OpenAI embeddings with cosine-similarity search over local NumPy vectors.

Source-grounded chat

Answers constrained to retrieved chunks, with a per-answer Sources button.

Full state handling

Loading, empty, validation-error, network-error, and backend-error states throughout.
